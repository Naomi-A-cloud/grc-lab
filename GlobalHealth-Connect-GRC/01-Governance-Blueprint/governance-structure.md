# GlobalHealth Connect Governance Structure

## Objective

The objective of the proposed governance structure is to establish clear accountability, decision-making authority, reporting lines and escalation processes for information security at GlobalHealth Connect.

## Proposed Governance Structure

The proposed structure is:

Board of Directors
↓
Chief Executive Officer (CEO)
↓
Information Security Governance / Security Steering Committee
↓
CTO / IT Manager / Compliance Officer
↓
Technical and Business Teams

## Governance Roles

### Board of Directors

The Board provides overall oversight of information security governance.

Responsibilities:

- Approve the overall security direction.
- Review significant information security risks.
- Receive regular security reports.
- Provide oversight of major security incidents.
- Ensure security supports business objectives.

### Chief Executive Officer (Sarah Chen)

The CEO provides executive leadership for information security.

Responsibilities:

- Ensure security is aligned with business objectives.
- Support security governance decisions.
- Approve major security priorities.
- Escalate significant risks to the Board.
- Ensure management responds to major security issues.

### Chief Technology Officer (Elena Rodriguez)

The CTO is responsible for technical security leadership.

Responsibilities:

- Oversee technical security controls.
- Manage security requirements for cloud systems.
- Review technical security risks.
- Work with the IT Manager on security operations.
- Report significant technical risks to the Security Steering Committee.

### Chief Financial Officer (Marcus Thorne)

The CFO provides financial and business oversight.

Responsibilities:

- Review security investments and resource requirements.
- Support funding for security improvements.
- Consider the financial impact of security risks.
- Participate in major risk decisions where financial impact is significant.

### Security Steering Committee

The Security Steering Committee provides cross-functional security governance.

Responsibilities:

- Review security risks.
- Review security performance and metrics.
- Approve or recommend security priorities.
- Monitor remediation activities.
- Resolve security governance issues.
- Escalate significant risks to executive management.

### IT Manager (John Smith)

The IT Manager is responsible for implementing and maintaining operational security activities.

Responsibilities:

- Implement approved security controls.
- Manage IT security operations.
- Track vulnerabilities and remediation.
- Support incident response activities.
- Report operational security issues.

### Compliance Officer (Mark Johnson)

The Compliance Officer provides compliance oversight.

Responsibilities:

- Monitor applicable regulatory requirements.
- Support compliance assessments.
- Identify compliance gaps.
- Track compliance-related remediation.
- Report significant compliance risks.

### Senior Developer (Jane Doe)

The Senior Developer supports secure development practices.

Responsibilities:

- Apply secure development practices.
- Identify application security issues.
- Support remediation of application vulnerabilities.
- Participate in security reviews.

### HR Manager (Robert Green)

The HR Manager supports people-related security requirements.

Responsibilities:

- Support security awareness activities.
- Support employee onboarding and offboarding controls.
- Maintain security responsibilities within HR processes.
- Support disciplinary processes related to security policy violations.

### Data Analyst (Emily White)

The Data Analyst supports data-related activities and reporting.

Responsibilities:

- Support security metrics and reporting.
- Identify data-related risks.
- Support data protection activities.
- Report identified data security issues.

## Decision and Escalation Process

Security issues should follow a defined escalation process:

1. Security issue is identified.
2. The responsible team assesses the issue.
3. The issue is recorded and assigned an owner.
4. The IT Manager or Compliance Officer reviews the issue where appropriate.
5. Significant risks are presented to the Security Steering Committee.
6. High-impact or unresolved risks are escalated to the CEO.
7. Major risks requiring Board oversight are reported to the Board.
8. Remediation actions are tracked until closure.

## Governance Principles

The proposed structure is based on three key principles:

### Clear Accountability

Every important security activity should have a clearly assigned owner.

### Risk-Based Decision Making

Security decisions should be based on the level and potential impact of the risk.

### Executive Oversight

Significant security risks should be visible to senior management and the Board.

## Expected Outcome

The proposed governance structure will provide GHC with clearer accountability, stronger executive oversight and a consistent process for managing security risks and escalating important issues.
