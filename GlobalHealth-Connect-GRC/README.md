# GlobalHealth Connect - Information Security Governance

## Project Overview

This project presents an information security governance assessment for GlobalHealth Connect (GHC), a fictional mid-sized health-tech organisation.

The project applies practical GRC concepts to assess governance weaknesses, define accountability, improve security reporting, support security decision-making, and develop a governance maturity improvement roadmap.

The project is designed to demonstrate how information security governance can support business objectives, risk management, compliance, and security operations.

## Organisation

GlobalHealth Connect is a fictional mid-sized health-tech organisation that operates a cloud-based patient management platform.

The organisation is experiencing rapid growth and has expanded through acquisitions. A recent data-leakage near-miss highlighted weaknesses in its existing security governance approach.

The Board has therefore requested a more structured approach to information security governance.

## Project Objectives

The project aims to:

- Assess the organisation's current governance weaknesses.
- Define security roles and accountability.
- Develop an Information Security Charter.
- Create a Risk and Governance RACI matrix.
- Present security metrics for Board-level decision-making.
- Establish a Security Steering Committee.
- Assess governance maturity.
- Develop a 12–18 month governance improvement roadmap.

## Project Areas

### 1. Governance Blueprint

Includes:

- Current-state governance gap assessment
- Governance structure
- Roles and responsibilities
- RACI matrix
- Decision and escalation responsibilities

### 2. Information Security Charter

Includes:

- Purpose and scope
- Governance authority
- Security roles and responsibilities
- Security principles
- Reporting requirements
- Review and approval process
- CFO justification memo

### 3. Board Security Reporting

Includes:

- Security metrics
- Security trends
- Board executive summary
- Risk and business impact analysis
- Security dashboard

Key metrics include:

- Phishing attempts
- Malware incidents
- Critical vulnerabilities
- Patching performance
- Security training
- High-risk security incidents

### 4. Security Steering Committee

Includes:

- Security Steering Committee Terms of Reference
- Meeting agenda
- Password policy review
- Risk-based decision-making
- CEO briefing

The committee scenario demonstrates how security decisions can be evaluated by balancing security risk, business requirements, and user experience.

### 5. Governance Maturity Assessment

Includes:

- Governance maturity assessment
- Six governance domains
- Current maturity levels
- Key governance gaps
- 12–18 month improvement roadmap
- Board executive summary

The assessment uses a five-level maturity scale:

1. Ad Hoc
2. Initial
3. Defined
4. Managed
5. Optimising

The current overall maturity assessment is Level 2 — Initial, with a target of Level 3 — Defined.

## Key Governance Findings

The assessment identified several governance weaknesses:

- Security policies are inconsistent or outdated.
- Security ownership is not always clearly defined.
- Risk management is mainly reactive.
- Security metrics are not consistently connected to business impact.
- Security training engagement is low.
- Compliance activities are mainly driven by audits.

The proposed governance improvements focus on accountability, risk management, reporting, awareness, compliance, and continuous improvement.
